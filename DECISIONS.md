This is the public manifest. It records decisions about the kit itself. It contains nothing about
any adopter.

## Core Goal

Package a design-first working method for coding agents as one installable Claude Code plugin,
with the adopter's personal layer generated by interview rather than inherited.

## Non-Negotiable Constraints

- A grade above HONOUR exists only where the kit or the adopter's brain ships the mechanism. The
  generator refuses otherwise.
- No hook is ever silent. An internal error allows the action, logs it, and surfaces it.
- `LAW.md` is generated from `law.json`. A hand edit turns the Doctor red.
- No third-party packages. Nothing runs on a timer, a cron, or at login.
- The kit never writes a user-level `settings.json`.
- Clause ids are permanent.

## Chapter 1 — Shape

**1.1 Container.** One repository that is also a plugin: commands, hooks, one agent, the Doctor,
the law generator, templates. Locked 2026-10-06.

**1.2 Platform.** Windows + PowerShell 7 in V1. Bash twins are a Change Request. Locked 2026-10-06.
Changed 2026-10-17 by CR-2026-10-17-NODE (0.2.0): Node.js 18 or newer on Windows, macOS and Linux,
with git on PATH and no packages. Every hook, the Doctor, the law build, adopt, remove, the commit
check and the docs build are `.mjs` scripts run by `node`; the brain shims are `Doctor.bat` and
`doctor.sh`, the commit shim is `sh` calling `node`. One code path serves every system: no Bash or
PowerShell twins.

**1.3 What ships.** `/design-first:adopt`, `/design-first:remove`, a read-only `reviewer` agent,
four generic commands (gut, move, scope, ship), three hooks, the Doctor, the generator. No skins,
no project-specific skills. Locked 2026-10-06.

## Chapter 2 — Mechanism

**2.1 Two LAW outputs.** Kit `LAW.md` carries the kit's grades. A brain's `LAW.md` is generated
from kit + overlay with grades re-derived from what is installed on that machine.

**2.2 Grades are mechanical.** DENY = a permission deny rule. HOOK / ADVISE = a hook, as its
anchor declares (`mode: deny` / `mode: advise`). GATE = an ask rule, a Doctor claim, or a tool
refusal; a tool refusal is an anchor line `mode: gate` in the script, never a bare file name. BUILDABLE = specified,
not shipped. OWNER = a standing ruling. HONOUR = a request. Each clause carries a verb; each
anchor declares the verbs it covers; the generator checks the match.

**2.3 Guard order.** Quote-aware tokeniser → staging rule on `git add` / `git commit -a` arguments
(wildcard adds probe untracked files) → history rule → `.env` write rule via git's own ignore and
tracking checks → path rules from the brain. No brain: the first three still run.

**2.4 Onboarding.** A command asks one question at a time; a script writes every file and records
what it wrote. Attach mode never overwrites. Remove deletes only unmodified kit-authored files.

**2.5 Subagent policy (2026-10-08, Change Request on DES-11).** A hook on the Agent tool: (1) a
brief without the contract headings is denied; (2) a call that names no model gets one from the
brain's role table by agent type, an explicit model always winning; (3) spawns are counted per
turn and the hook asks above the cap. Tunables in `<brain>/agent-policy.json`, template in the
kit. DES-11's text changed to say what the hook checks; the old fan-out-by-file-count rule became
body guidance ("parallelise independent decisions, not files"). Whether the host honours a
rewritten `model` was not documented, so it was proven by a live probe rather than assumed:
2026-10-08, Claude Code desktop, plugin 0.1.2, an `Explore` spawn with no model named was
rewritten to `haiku` by the hook and the subagent reported its own model id as
`claude-haiku-5-5`. The routing half is a guarantee on that host; re-run the probe after a host
upgrade.

**2.6 The law by route (2026-10-08, DES-13).** A UserPromptSubmit hook matches each prompt
against a per-group word list in `<brain>/route-policy.json` (and the working folder), and injects
a group once per session as its rows from the generated `LAW.md` with the owning files resolved.
Routes stick for the session; the entry hook clears them on compaction. A SubagentStart hook
injects the session's active groups plus always-on groups into every subagent. The entry path
shrinks to the personal layer. Three owner decisions: personal layer at start and law by route;
subagents get the session's groups; a new clause DES-13 at ADVISE rather than rewording PRIN-01.
*Superseded in part 2026-10-15 (CR-2026-10-15-GAPS D5): the entry hook clears the session's routes on a compaction or a clear, so the next prompt re-injects.*

**2.7 Planned mechanisms (2026-10-08, the HONOUR triage).** Every clause was triaged with the
owner: a mechanism that exists is cited; a mechanism that is specified but not shipped prints
BUILDABLE and points here; a standing ruling prints OWNER; a request stays HONOUR with its reason in
the owning file. The planned mechanisms, each a Change Request when built:
- *Repo scan* (claim type `tree_each`): **shipped in 0.1.6.** For every git repository under a
  root that matches a shape, require files, globs or strings; a repository born before `since`
  is reported, not failed (the ratchet, from git's first-commit date); `accepted` entries need a
  reason. Carries DES-01, OBS-01, OBS-05, OBS-08, OBS-09 and the brain's GAME-15 and GAME-16.
  The kit's own grade for those clauses stays BUILDABLE: the kit cannot assert a fact about an
  adopter's repositories, so the claims live in the brain (two generic ones ship in
  `templates/claims.json`), and the brain overlay re-grades the clauses to GATE.
- *Regex scan* (claim type `tree_rules`): **shipped in 0.1.8.** Same selection and ratchet as
  `tree_each`; per repository, files matching a glob are read and each rule applied: `forbid`
  (no line may match, unless that line or the one above carries the `allowOnLine` reason) or
  `when` + `require` (a file that matches the one must match the other). Carries SAFE-05,
  OBS-04, SKIN-03, SKIN-04 and GAME-07 through brain claims. Written residual for OBS-04: a
  stderr redirect on a command whose exit code is read is not a swallowed error and cannot be
  told apart by regex, so the claim counts only an empty catch and a bare except.
- *Stop hook*: **shipped in 0.1.7** (`hooks/stop.ps1`, owner decision: block once, then yield).
  The guard records every allowed edit of the turn in a ledger; when the turn changed source,
  the first attempt to stop is refused with the card (documents touched, the Change Log row when
  DECISIONS.md changed, the cross-check, the Definition of Done) and the second attempt passes.
  Carries DES-07, GATE-05, GATE-06, GATE-07 at HOOK. It requires the card, it cannot grade the
  answer. **Scope, corrected in 0.1.9:** an edit counts only inside a git repository, and only
  under the root when the pointer names one. The first live card named the session scratchpad
  as a repository, because a path in no repository was grouped under its own folder.
  **Source of truth, corrected in 0.1.15:** what changed is read from git, not from the tool
  calls. The guard nominates every repository a call points at and records the commit HEAD is
  on; at the stop, git names the files committed since then and the uncommitted files written
  since the prompt. The ledger of Edit and Write calls stays as the fallback and for files git
  ignores. A background-task notice is no longer taken for a prompt.
- *Ratchet claim* (claim type `ratchet`): **shipped in 0.1.10** (owner decision: a signed raise).
  The Doctor reads one integer from a row of a generated markdown table (the HONOUR row of the
  LAW.md Summary) and compares it with the value recorded on the last run in `state/ratchets.json`.
  A fall tightens the record. A rise is RED and the record does not move, so a re-run stays RED.
  The valve is `accepted: { value, since, reason }` on the claim, in git; it is spent the first
  time it lets a rise through, so it cannot become a standing ceiling. Carries PRIN-04 at GATE
  through `KIT-RATCHET-01` (the kit's own LAW.md); `templates/claims.json` ships
  `RATCHET-HONOUR-01` for an adopter's LAW.md. Written limit: the record is local state, so a
  fresh checkout records its own baseline.
- *Survey finding* `outsideCategory`: **shipped in 0.1.11.** With `categories.folders` set in the
  brain config, a live repository whose first folder under root is not one of them is reported.
  The ratchet is the one the owner chose for the repo scan: git's first-commit date against
  `categories.since`. Born before it: a warn, folded into one backlog line. Born on or after it,
  or no commit yet: a fail, which is RED under `surveyStrict`. Never reported: the root, the
  brain, the root's `.claude` folder. `acceptedExceptions` takes the kind. The kit has no clause
  for this; a brain cites the anchor `survey-outside-category` (verb `place-project`).
- *Entry hook, game repositories*: **shipped in 0.1.13** (`hooks/lib/state-card.ps1`, called by
  `entry.ps1`). A session that starts inside a repository whose top-level folder the route policy
  maps to a `stateCard.groups` group gets a card after the entry path: git's facts, the manifest's
  goal, timeline position, last Change Log row and open questions, the hand-off's state and next,
  each document with its age in commits, a STALE flag past `staleCommits`. Carries GAME-13 at
  ADVISE: the hook prints, the agent posts and compares. Written limit: it fires only when the
  session starts in the repository.
- *Brain commit check*: **shipped in 0.1.12** as `tools/vcs/law-claim.ps1` behind the shim
  `templates/commit-msg` (owner decision: refuse, with a written waiver). A commit that changes a
  law file is refused unless claims.json is in it or the message carries `No-Claim: <reason>`. It
  is a `commit-msg` hook and not a `pre-commit` hook, because only `commit-msg` can read the
  message. The law-file list is read from the brain's LAW.md at commit time. VCS-23 stays
  BUILDABLE in the kit: `adopt` does not install the shim yet, so the kit cannot say a given
  adopter has it. A brain that installs it re-grades the clause in its overlay (anchor
  `law-claim`) and proves the shim with two claims. Open: install and remove through `adopt`.
  *Superseded 2026-10-15 (CR-2026-10-15-GAPS D4): DES-07, GATE-01, GATE-05, GATE-06, GATE-07 and GAME-12 are ADVISE, because the card asks once per source turn and grades nothing. The card names every clause it carries, asks for the verify gate's command and pasted output (GAME-12), and asks on every card whether the turn needs a Change Request (GATE-06).*
  *2026-10-15 (CR-2026-10-15-GAPS D7): VOICE-05 is BUILDABLE for the same reason as VCS-23: adopt does not install the commit-msg shim. A brain re-grades VOICE-05 to GATE only when the shim is in every repository the owner commits to, with a claim that checks that.*

**2.8 The HONOUR audit (2026-10-13, CR-2026-10-13-HONOUR).** The owner read the generated page,
which printed 37 rules enforced by nothing, and ruled: a rule nothing fires is not a rule. Every
HONOUR clause was triaged again, one verdict each, no relabels: a mechanism that exists or is
small gets built and the generator grades it; a clause only a reader can judge becomes ADVISE
through a real per-action injection; a clause the loop runner enforces prints BUILDABLE and points
here; nothing was cut. Target: HONOUR 0, the ratchet then holds it. Shipped in chunks:
- *advise-by-role* (`hooks/subagent.ps1#advise-by-role`, 0.1.22): when a subagent starts, the
  hook reads every clause whose `enforcedBy` names this anchor, from the kit's `law.json` and the
  brain's overlay, and injects them after the law groups with one instruction per role. The
  Reviewer's report gains an `ADVISE` section that names each id as `holds` or as a finding with a
  place; an id not looked at is `BLOCKED`. A Builder is told the Reviewer will name them. Carries
  18 clauses at ADVISE. The route hook's group rows stay the per-session half.
- *skills* (`hooks/route.ps1#skills`, 0.1.22): the prompt is matched, whole words of five letters
  or more, against the name and description of every `SKILL.md` under `root\.claude\skills` and the
  profile's `.claude\skills`; a match is named once per session with its path. Carries DES-12.
- *stop-done* carries GAME-12 from 0.1.22: the Stop hook already was the inner gate; the clause
  had never claimed it.
- *The loop runner* (planned; the owner's harness loop, outside the kit): the stop list (AUTO-02),
  the deterministic pass mark (AUTO-07), the new-probe rule (AUTO-08), one process per story
  (AUTO-10) and the start conditions (AUTO-12) are its behaviour. They print BUILDABLE until the
  runner ships in the kit or the brain overlay re-grades them against a shipped copy.
- *interview* (`hooks/stop.ps1#interview`, 0.1.23): `ask.ps1` writes a session marker on every
  allowed question; a repository whose `.git` was created since the prompt, with source changed
  and no marker, gets the GATE-01 line on the Stop card. Carries GATE-01 at HOOK.
- *design-gate* (`hooks/guard.ps1#design-gate`, guard rule 10, 0.1.23): `Design gate: on` in a
  repository's DECISIONS.md refuses every source write until `records/gate-cleared.md` exists
  and reads clean: `Findings: <n>` above zero, one `- ` line per finding marked resolved or
  recorded. Documents stay writable. Carries GATE-08 and GATE-09 at HOOK, one grade higher than the
  triage's GATE for GATE-09, because the same rule that opens the gate reads the record.
- *loop-no-push* and *ledger* (`hooks/guard.ps1#loop-no-push`, `#ledger`, guard rules 11 and 12,
  0.1.24): the current branch name is the one fact both read; a branch with the loop prefix
  (`loopBranchPrefix`, default `harness/`) refuses push, merge and pull, and refuses edits to the
  story ledger (`loopLedgerGlobs`). Carries AUTO-11 and AUTO-04 at HOOK. No marker file: git holds
  the fact.
- *MAP-01 on frozen-path* (owner decision 2026-10-13): the brain's canonical.md is prose; its
  enforced half already exists as `frozenPaths` and `tombstonedPaths`, which the frozen-path rule
  refuses. Offered: a Copies table in canonical.md for the guard to parse. Chosen: no new table, no
  parsing of prose; a copy that must not be edited is listed as frozen. Carries MAP-01 at HOOK.
- *state-once* and *no-count* (`tools/law/build-law.ps1#state-once`, `#no-count`, 0.1.25): the
  generator fails when a clause's `### ID` heading is in two law files, in none, or in a file other
  than its owner; and when a rule text carries a count (a number before a plural noun, or two or more
  digits). Carries PRIN-05 and SKIN-07 at GATE. Scope of no-count: the rule text, not the prose.
- *commit-message* (`tools/vcs/law-claim.ps1#commit-message`, 0.1.25): the same shim the brain
  installs refuses a subject over 72 characters, a past-tense first word or a bare placeholder;
  merges and reverts exempt; tunables under `commitMessage`. Carries VOICE-05 at GATE. The check
  runs in every repository the shim is installed in; the law-claim check still applies to brains only.
- *file_fresh* and *config_paths_each* (claim types, `tools/doctor/claims-fresh.ps1`, 0.1.26):
  `file_fresh` reads the last line that starts with an ISO date and fails when it is older than
  `maxDays`, when there is no dated line, or when the file is missing (nothing proved is a fail,
  not could-not-look). `config_paths_each` reads a list of folders from a config key or the claim
  and requires a named file with named strings in each; an empty list passes and says so. Kit
  claims `KIT-RESTORE-01` (the kit ran a real drill on 2026-10-13: clone, compare HEAD, count
  files, log one line) and `KIT-TOMBSTONE-01`; brain templates `RESTORE-01` and `TOMBSTONE-01`.
  Carries VCS-06 and VCS-12 at GATE. DISP-07 rides `KIT-DOCS-01`, the page's own
  `generated_matches` claim, at GATE: the kit's one figure-bearing page cannot carry a typed count.
  With this chunk HONOUR reads 0 and the ratchet holds it there.

## Chapter 3 — The page (chunk 10, 2026-10-13)

The public page for the kit. Owner decisions from the interview on 2026-10-13, one question at a time.

**3.1 Home.** Source in `docs/` of this repo. Since 0.2.7 the site does not carry a copy of this
page: `docs/publish.mjs` writes the kit's facts to `method/data/kit.json` on the owner's one site,
and the site's method page renders them. Before 0.2.7 the published copy lived at
`tools/design-first/`, put there by `docs/publish.mjs`, and registered in that site's
`data/registry.json`. This repo gets no GitHub Pages of its own (owner rule: one live site, a code
repo behind every page). Offered: own Pages (breaks the one-site rule); site-only (the parts list
would be typed, not generated). **Change Rule:** moving the published copy is a one-line edit in
`publish.mjs`; giving this repo its own Pages is a Change Request.

**3.2 Composition.** Research pass first (GitHub, Hacker News, Exa; Reddit is not configured on
the build machine). Rejected: every docs framework and "terminal hero" block, because they are the
generic shape. Chosen: scrollycoding (the mechanic behind Code Hike and scrollama, both MIT) with
one explorable moment inside it (Waveforms, MIT). The bible's generation contract (WEB-11):

```json
{
  "site_type": "method explainer",
  "dominant_idea": "A rule is only a rule when something on the disk can stop you; the page shows what stops you, step by step.",
  "primary_patterns": ["interactive_explainer", "editorial_rhythm", "motion_choreography"],
  "narrative_sequence": ["promise", "the flow (six beats, pinned stage)", "the parts (typographic index)", "the grade dial", "limits", "install and license"],
  "persistent_clusters": ["identity_navigation (Home, title)", "orientation_progress (chapter rail)", "primary_action (install)"],
  "card_policy": "none; the parts are a typographic index, the clauses a table that reflows",
  "responsive_transformations": ["below 960px the pinned stage sits inline under its step", "the chapter rail becomes a top strip", "the clause table reflows to one column per row"],
  "reduced_motion_equivalent": "every stage state rendered static in document order; no typing, no swap"
}
```

Case studies read, with their risks: Contra Project Cost Calculator (one step at a time hides total
effort, so the chapter rail shows progress), A Spacecraft for All (spectacle can hide the
narrative, so the stage never moves while the reader is on a step), Clear Street (oversized claims
need nearby substantiation, so every count on the page is generated).

**3.3 Nothing on the page is typed.** `docs/build.mjs` renders `docs/index.html` from
`docs/src/template.html` and the kit's own files: `law.json` (groups, grades, clauses, mechanisms),
`hooks/hooks.json` (events, matchers) with each hook script's first comment line, `tools/doctor/claims.json` (claim types), `commands/*.md`
(names, descriptions), `.claude-plugin/plugin.json` (version), and the README's method list, grade
table, limits and install block. The terminal transcript is a
recording of a real `adopt.mjs` and `doctor.mjs` run on a scratch root, stored in `docs/src/`
with the date and kit version, machine paths replaced by `C:\adopter`. A `generated_matches` claim
(`KIT-DOCS-01`) makes a hand edit of `index.html` RED. Since CR-2026-10-18-READ the same builder
renders the README's inventory block, between its markers, from `ARCHITECTURE.md`'s Domains table
and `hooks.json`; `KIT-README-01` makes a hand edit there, or a tree change with no rebuild, RED.
Since CR-2026-10-19-START it renders two more README blocks the same way: what adopt asks and
writes, from `commands/adopt.md` and the plan in `tools/lib/adopt-plan.mjs`, and the commands,
from `commands/*.md`; `KIT-README-01` covers all three.
**Change Rule:** a new fact on the page or in the inventory is a new input to `build.mjs`, never a
sentence in the template or the README.

**3.4 Skin.** Its own token file, `docs/page.css` `:root`. Light page, one dark object: the stage.
The page is capped at `--page-max` (72rem) and centred, and the header, rail and footer share its
edges, so a wide screen gets margins (CR-2026-10-19-START: the owner ruled the full-width page the
wrong call; it followed the width half of the style bible's WEB-14, "desktop uses all of the
width", which the owner's site already broke for its front page in its CR-21).
No framework, no build tool, no dependency; the step observer is an IntersectionObserver in
`docs/page.js`. The page survives JavaScript off: every stage state is in the HTML after its step
in document order; the script only pins and swaps. **Change Rule:** a dependency is a Change Request.

**3.5 Motion.** The stage swaps when a step reaches the middle of the viewport (orient, causality).
Typing runs only inside the stage, only after its step is reached, once. Under
`prefers-reduced-motion` nothing moves and nothing types. No ambient loop. The chapter rail marks
the current beat (confirm). **Change Rule:** any motion with no job in WEB-06 is removed.

**3.6 The explorable.** The grade dial: a list of every clause; pick one and the page shows its
grade, the mechanism that enforces it and the verb that mechanism uses, from `law.json`
`enforcedBy`. One control, keyboard-complete, every state linkable by clause id. The honest
sentence beside it is generated: how many clauses nothing enforces.

**3.7 Limits on the page, verbatim from the README.** Windows and PowerShell 7 only, one adopter
per profile, the guard does not see nested shells. The page states them before the install block.

**3.8 The page teaches the method (2026-10-17, owner ruling after an outside reader).** A reader
of the kit took "chunk" to mean one department interviewed and built end to end, then the next,
and the page gave him nothing to check that against. The owner's ruling: the page is the kit's
educational face, and it keeps everything 3.3 generates. Three chapters go in before the flow.
*The method:* a drawing of the two ways to split a build (parts interviewed and built one by one,
against decide-all-then-one-domain-at-a-time), the README's "The method, on one page" list read
by `build.ps1`, and the README's worked example. *The gates:* the `LOOPS.md` overview redrawn as
three inline SVG figures (the straight path; the five loops each with what it costs; both
married), followed by the overview as it is kept in `LOOPS.md`, chart and steps, read by
`build.ps1`. *The words:* fourteen definitions, each with the meaning it does not carry, and a
"what this method is not" list. The drawings and the definitions are typed in the template, which
3.3 allows for prose; the facts they cite are checked: `build.ps1` fails when the template cites a
clause id that is not in `law.json`, the same check `cases-loops.ps1` runs on `LOOPS.md`. The
figures use the grade colours (refusal red, GATE blue, HOOK green) so a colour on a drawing means
what it means on a grade chip. **Change Rule:** a step added to the `LOOPS.md` overview is drawn
into the three figures in the same commit, or the figures come out; a new definition is a
Change Request.
