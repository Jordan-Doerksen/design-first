# {{OWNER_NAME}}'s brain — ARCHITECTURE

## System at a glance

The private layer of design-first. The kit is a plugin the sessions run; this folder is what the
kit reads about its owner: identity, voice, prohibitions, the overlay to the law, the claims and
config the Doctor checks, the lessons, and the generated `LAW.md`. Everything resolves through the
pointer in the user profile: root `{{ROOT}}`, brain `{{BRAIN}}`.

## Stack

| runtime | version | pinned by | lockfile | install | why |
|---|---|---|---|---|---|
| Node.js | 18 or newer | the kit's README | none; no packages | none | the kit's hooks, Doctor and law generator, which the shims here call |
| git | any on PATH | none | none | none | the Doctor's repository scan and the commit-msg shim |

The brain's stack is the kit's. A runtime this table does not name is a Change Request (GATE-06).

## Core flow

```
kit law.json + law.overlay.json + state/law-installed.json --> build-law.mjs --> LAW.md (here)
claims.json + doctor.config.json --> Doctor.bat or doctor.sh (shim) --> the kit's doctor.mjs --> state/
me.md, voice.md, entry.json --> hooks/entry.mjs --> the first turn of every session
route-policy.json --> hooks/route.mjs --> law rows per prompt
```

## Domains

| file or folder | purpose | config | notes |
|---|---|---|---|
| `me.md`, `voice.md` | who the owner is; how their copy reads | — | read on turn one (entry path) |
| `prohibitions.md` | the owner's own hard rules | — | owning file for overlay SAFE clauses |
| `law.overlay.json` | clauses and re-grades on top of the kit's law | — | one `### ID` heading per clause under `instructions/` |
| `LAW.md` | the generated index | — | never hand-edited; `BRAIN-LAW-01` builds it again on every Doctor run and is RED on any difference, so rebuild it after a plugin update that changes the law |
| `claims.json` | facts the Doctor checks | — | a law file that states a fact about the disk gets a claim |
| `doctor.config.json` | the Doctor's and the hooks' tunables | itself | frozen and tombstoned paths, owners, categories, hook knobs |
| `entry.json`, `route-policy.json`, `agent-policy.json` | the entry path, the route words, the subagent policy | themselves | |
| `lessons.md`, `canonical.md` | lessons that became rules; which copy is canonical | — | the enforced half of canonical.md is `doctor.config.json` |
| `records/` | restore drills, gate records, dated logs | — | read by claims, written by people |
| `state/` | generated by the Doctor and adopt | — | gitignored; `installed.json` is what `/design-first:remove` reverses; `law-installed.json` is what the law build reads |
| `entry-point/` | byte snapshots of the root entry files | — | compared by the Doctor |

## How to modify a domain

Read `DECISIONS.md`. Change config before logic: most changes here are a list in
`doctor.config.json` or a clause in `law.overlay.json`. Regenerate `LAW.md` after any overlay
edit. Run `Doctor.bat` (Windows) or `./doctor.sh` (Linux, macOS). Add the Change Log row.
